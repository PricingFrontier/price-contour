# Price Contour — Engineering Review

**Date:** 2026-03-16
**Scope:** Full codebase review — Rust core, PyO3 bindings, Python orchestration, tests, performance, security
**Method:** 10 parallel Opus agents, each specialising in a different area

---

## Executive Summary

The core algorithm is correctly implemented. Memory layout is cache-optimal for the access patterns. Rayon parallelism is sound with no data races. The `Arc<QuoteGrid>` sharing pattern is well-designed. The test suite has excellent property-based tests via Hypothesis. Dependencies are minimal and well-maintained. No `unsafe` code anywhere.

The primary gaps are: (1) no systematic input validation boundary — nulls silently drop, NaN causes panics, dimension mismatches go unchecked; (2) significant DRY violations across both Rust and Python; (3) test coverage gaps in Rust-level unit tests; (4) a trivial build flag change that unlocks 1.3–1.7× speedup.

| Severity | Count | Key Themes |
|----------|-------|------------|
| Critical | 3 | Silent null dropping, NaN panics, missing specs/constraints validation |
| High | 12 | Dead tolerance param, GIL not released, unbounded scale factors, no Python-side validation, HashMap non-determinism |
| Medium | ~25 | DRY violations, thread-unsafe mutation, missing derives, dead error variants |
| Low | ~20 | Documentation gaps, cosmetic issues, minor edge cases |

## Section 1 — Architecture

### Issue 1: No systematic input validation boundary (CRITICAL)

The library has no consistent validation layer. It manifests as ~10 specific bugs:

- `into_no_null_iter()` silently drops null values (`solver_py.rs:136,147`, `builder_py.rs:256,267`) — produces shorter vectors, corrupting grid layout.
- NaN/Inf in data causes panics via `partial_cmp().unwrap()` (`data.rs:74`, `frontier.rs:72,125`, `grouped.rs:22`) or silently corrupts argmax results.
- No Python-side validation — wrong types, missing columns, empty DataFrames all hit cryptic Rust errors.
- `specs.len() != grid.constraints.len()` never checked (`online.rs:20`, `argmax.rs:40`) — causes out-of-bounds or silently ignores constraints.
- `initial_lambdas` length not validated (`online.rs:39`) — wrong-length lambdas silently truncated by `zip()`.
- `residuals`, `candidates`, `group_mapping` not validated in `solve_grouped` (`grouped.rs:212`) — wrong lengths cause panics.
- `factors` DataFrame row count not validated against grid quote count (`ratebook.py:173`) — silently wrong results.
- `n_steps=0` not rejected by `validate()` — panics at `argmax.rs:77`.
- `chunk_size=0` not rejected — infinite loop in `online.rs:73`.
- Constraint dict shape not validated on init — invalid structures only caught deep in Rust.

**Decision:** Layered validation architecture — Python `__init__` validates config shape, Python `solve()`/`apply()` validates DataFrame schema + nulls + types before crossing FFI, Rust `validate()` extended to check `n_steps>0`, `n_quotes>0`, NaN/Inf in `scenario_values`, and all dimension mismatches.

### Issue 2: `SolverConfig.tolerance` is dead code (HIGH)

`tolerance` is stored in `SolverConfig` (`data.rs:115`) with a default of `1e-6`, but never read by any solver. Convergence checks use hard-coded constants `LAMBDA_CONVERGENCE_TOL` and `CONSTRAINT_SATISFACTION_TOL`.

**Decision:** Wire `config.tolerance` into the convergence checks, replacing the hard-coded constants.

### Issue 3: GIL not released during Rust computation (HIGH)

None of the PyO3 functions release the GIL before calling into the core solver. The Rust core is pure computation with no Python object interaction.

**Decision:** Add `py.allow_threads()` to all compute functions (~6 call sites).

### Issue 4: HashMap iteration order makes constraint ordering non-deterministic (HIGH)

`constraint_cols` is built from `HashMap::keys()` (`solver_py.rs:442`, `apply_py.rs:95`). Rust's `HashMap` doesn't guarantee iteration order.

**Decision:** Sort constraint names alphabetically after collection.

### Issue 5: Error type architecture — opaque strings + dead variants (MEDIUM)

Four of five error variants carry plain `String`. `ConvergenceFailure` is defined but never constructed. `MissingColumn` appears unused.

**Decision:** Remove dead variants, add consistent PyO3 error wrapping prefixes. Keep string payloads (structured fields are over-engineering for the current error surface).

### Issue 6: Frontier sweep aborts on single solve error (HIGH)

`sweep_frontier` uses `?` on each `solve_online` call — one failing point kills the entire sweep. No aggregate convergence summary exists.

**Decision:** Catch and skip failed points with a warning count. Add `n_converged: usize` to `FrontierResult`.

### Issue 7: Thread-unsafe `self.constraints` mutation in ratebook frontier (HIGH)

`RatebookOptimiser.frontier()` temporarily overwrites `self.constraints` within a `try/finally` block.

**Decision:** Refactor `solve()` to accept an optional constraints override parameter instead of mutating instance state.

### Issue 8: `_RatebookFrontierResult` vs `FrontierResult` type inconsistency (MEDIUM)

The Rust `FrontierResult` has `sv_*` columns. The Python `_RatebookFrontierResult` lacks them. No shared Protocol enforces the interface.

**Decision:** Define a `FrontierResultProtocol` in `frontier.py`, document the sv_stats gap.

### Issue 9: Missing standard derives on public types (MEDIUM)

No public struct has `Debug` or `Clone`.

**Decision:** Add `#[derive(Debug, Clone)]` to all public types. `Debug` only for `QuoteGrid` (to avoid multi-GB clone).

### Issue 10: `QuoteGrid` encapsulation — `ingest_dataframe` skips `validate()` (MEDIUM)

All `QuoteGrid` fields are `pub`. `ingest_dataframe` constructs a grid without calling `validate()`.

**Decision:** Add `validate()` call in `ingest_dataframe`. Keep fields `pub` since tests benefit from direct construction and all solver entry points already validate.

### Issue 11: Missing `.pyi` stub files for Rust extension (MEDIUM)

No `.pyi` stubs exist for the `_price_contour` extension module.

**Decision:** Generate stubs with `pyo3-stub-gen`.

### Issue 12: Missing `history` and `dataframe` getters on `PyGroupedSolveResult` (MEDIUM)

`PyGroupedSolveResult` accepts `record_history=True` but doesn't expose a `history` getter. Also lacks a `dataframe` property.

**Decision:** Add both getters.

### Issue 13: `solve_from_grid_py` takes `&mut PyQuoteGrid` unnecessarily (LOW)

Never mutates the grid.

**Decision:** Change to `&PyQuoteGrid`.

### Issue 14: `baseline_totals()` recomputed redundantly per frontier point (LOW)

100 frontier points = 100 redundant `O(n_quotes)` passes on the same immutable grid.

**Decision:** Add an internal `solve_online_with_baselines()` variant. `sweep_frontier` computes once and passes.

## Section 2 — Code Quality

### Issue 15: DRY — Grid construction duplicated 4× in Python + duplicated Rust ingest/extract (HIGH)

Identical `QuoteGridBuilder` construction at `solver.py:146–154`, `ratebook.py:205–216`, `ratebook.py:347–358`, `ratebook.py:438–449`. Rust `ingest_dataframe` and `extract_chunk`/`extract_grid_info` also duplicate column extraction logic.

**Decision:** Extract `_ensure_grid()` in Python + shared `ingest_utils.rs` in Rust.

### Issue 16: DRY — Solver internals duplicated between `online.rs` and `grouped.rs` (MEDIUM)

Four patterns copy-pasted: chunked argmax loop (3×), scale factor computation (2×), constraint satisfaction check (2×), non-converged fallback (2×).

**Decision:** Extract shared helpers: `chunked_argmax_pass()`, `compute_scale_factors()` (or method on `QuoteGrid`), `all_constraints_satisfied()`, `select_final_lambdas()`.

### Issue 17: DRY — PyO3 bindings repeated patterns (MEDIUM)

`parse_constraints` + lambda ordering called from 6+ sites. zip-to-dict repeated ~10 times. Lambda ordering repeated at 5 sites.

**Decision:** Extract `order_lambdas()`, `zip_to_dict()`, and consolidate constraint prep.

### Issue 18: DRY — Cross-language duplication (MEDIUM)

`_nn_order`, `linspace`, `cartesian_product` implemented in both Rust and Python. Candidate generation duplicated within Python.

**Decision:** Fix Python-only duplication (`_build_candidates`). Accept cross-language duplication as pragmatic trade-off of hybrid architecture.

### Issue 19: Unbounded scale factors → numerical instability (HIGH)

Scale factor computation can produce values of 1e22+ when baseline constraint values are near-zero.

**Decision:** Cap with `MAX_SCALE_FACTOR = 1000.0` constant.

### Issue 20: Validation gaps — zero dimensions, overflow, empty vectors (HIGH)

`n_steps=0` panics, `n_quotes=0` wastes iterations, `chunk_size=0` infinite loops, empty `candidates` panics, `n_quotes * n_steps` can overflow.

**Decision:** Add all checks to `validate()` and solver entry points (5–6 one-line checks).

### Issue 21: Length mismatch validation gaps in solver APIs (HIGH)

`initial_lambdas`, `residuals`, `group_mapping`, `specs` lengths not validated against expected values.

**Decision:** Add explicit dimension checks at every solver entry point (~10 one-line checks).

### Issue 22: Constraint config validation gaps (MEDIUM)

Lambda key mismatch silent, constraint dict shape not validated on init, factor column existence not validated, auto-discovery fallback silently uses all columns.

**Decision:** Validate all at construction time. Add lambda key warning. Validate factor columns. Add warning for auto-discovery fallback.

### Issue 23: Frontier Cartesian product explosion (HIGH)

`n_points_per_dim^n_constraints` can produce millions of points with no cap.

**Decision:** Add `max_total_points: usize = 10_000` to `FrontierConfig`.

### Issue 24: Serialisation gaps (MEDIUM)

No version field in saved JSON, no schema validation on load, no `RatebookResult.load()`, redundant config keys.

**Decision:** Add version field, schema validation, `RatebookResult.load()`, remove redundant key.

### Issue 25: Minor solver correctness issues (LOW)

Clamp stats overwritten each iteration (not cumulative), ergodic average accumulates post-update lambdas (off-by-one), history records post-update lambdas with pre-update totals.

**Decision:** Fix all three (small reorders of existing code).

### Issue 26: Minor edge cases (LOW)

Colon in factor level values breaks `split(":")`, `summary()` NaN for 1-quote std, `frontier_summary()` no bounds check, population std dev undocumented, `pct_increase`/`pct_decrease` hard-codes 1.0.

**Decision:** Fix items 1–3 (actual bugs), document items 4–5 (design choices). Fix unnecessary `best_lambdas.clone()`.

### Issue 27: Code hygiene (LOW)

`PAR_GRAIN` inconsistent, constants undocumented, `1e-10` magic epsilon, `approx` unused, unused test fixture, redundant dict comprehension, `Any` type hints, docstring order.

**Decision:** Fix all (mechanical).

## Section 3 — Tests

### Issue 28: No Rust-level tests for `QuoteGridBuilder` (CRITICAL)

130 lines of validation logic with zero Rust-level tests. 8 untested code paths.

**Decision:** Add comprehensive Rust unit tests for all builder validation paths.

### Issue 29: No Rust tests for `build_group_mapping()` (HIGH)

Fundamental grouped solver dependency with zero tests.

**Decision:** Add 4–5 Rust unit tests.

### Issue 30: Null/NaN handling untested and known broken (CRITICAL)

Skipped test documents the gap.

**Decision:** Un-skip and fix after implementing Issue 1's validation layer.

### Issue 31: `min_abs`/`max_abs` constraint paths completely untested (HIGH)

Zero coverage at both Rust and Python levels.

**Decision:** Add Python integration tests for both modes.

### Issue 32: No multi-constraint Rust tests (HIGH)

All Rust solver tests use 0 or 1 constraint.

**Decision:** Add Rust tests with 2+ constraints including both Min and Max directions.

### Issue 33: No Rust error path tests for solvers (HIGH)

No tests verify error returns from solvers.

**Decision:** Add error path tests for all new validation checks.

### Issue 34: Frontier helpers untested (MEDIUM)

`percentile()`, `compute_sv_stats()`, `linspace()` have no direct tests.

**Decision:** Add direct unit tests for all three with edge cases.

### Issue 35: `is_df_sorted()` optimization path untested (MEDIUM)

30 lines of logic with no direct test coverage.

**Decision:** Add Python integration tests for sorted/unsorted paths.

### Issue 36: No interaction factor solve test for ratebook (MEDIUM)

Interaction factors tested only for `save()`, never through `solve()`.

**Decision:** Add interaction factor solve test.

### Issue 37: No 3+ constraint tests anywhere (MEDIUM)

All multi-constraint tests use exactly 2 constraints.

**Decision:** Add 3-constraint Python integration test.

### Issue 38: No fuzzing setup (MEDIUM)

No `cargo fuzz` targets despite complex f32 arithmetic and FFI boundary.

**Decision:** Add `cargo fuzz` targets for `solve_online` and `validate()` (lower priority).

### Issue 39: Rust floating-point assertions use brittle absolute tolerances (LOW)

All Rust tests use manual `abs() < 1e-6`. Declared `approx` crate is never imported.

**Decision:** Switch to `approx` crate macros.

### Issue 40: Test infrastructure cleanup (LOW)

Unused `solved_result` fixture, inconsistent tolerance documentation, dead error variant.

**Decision:** Clean up all three.

## Section 4 — Performance

### Issue 41: Missing `target-cpu=native` build flag — 1.3–1.7× potential (HIGH)

No `.cargo/config.toml` exists. Inner argmax loop is textbook SIMD but compiles to SSE2 only.

**Decision:** `target-cpu=native` for development, `x86-64-v3` (AVX2) for release wheels.

### Issue 42: Python O(n) loops in ratebook — 60–150s for 10M quotes (HIGH)

Three pure-Python loops iterate over all quotes per factor per CD iteration.

**Decision:** Vectorise with Polars expressions.

### Issue 43: Frontier sweep is sequential — 4–8× potential (MEDIUM)

All frontier points solved sequentially. Warm-starting requires sequential ordering.

**Decision:** Add configurable `parallel` option to `FrontierConfig`. When true, run points in parallel without warm-start.

### Issue 44: Redundant outer chunking in online solver — 5–10% (MEDIUM)

Outer `while` loop chunks quotes unnecessarily since `lagrangian_argmax_pass` already parallelises internally.

**Decision:** Remove outer chunking, pass full range. Modify `lagrangian_argmax_pass` to write directly into caller's buffer.

### Issue 45: `compute_sv_stats` sorts per frontier point (MEDIUM)

Full sort of `n_quotes` elements per frontier point.

**Decision:** Use `select_nth_unstable` for approximate percentiles (O(n) per percentile).

### Issue 46: Scattered `group_l` writes for many groups (MEDIUM)

Cache-unfriendly writes when quotes aren't ordered by group.

**Decision:** Do nothing — typical use has 5–50 groups. Revisit if profiling reveals bottleneck.

### Issue 47: `quote_ids: Vec<String>` memory overhead (MEDIUM)

100–200MB for 10M quotes. Only used for result DataFrame construction.

**Decision:** Do nothing — acceptable for machines processing 10M-quote portfolios.

### Issue 48: Constraint arrays as `Vec<Vec<f32>>` (LOW)

Pointer chasing for 5+ constraints.

**Decision:** Do nothing — typical use has 1–3 constraints. Refactoring cost exceeds benefit.

### Issue 49: Parquet reader loads full file (LOW)

No streaming for very large files.

**Decision:** Document limitation — `QuoteGridBuilder` exists for chunked ingestion.

### Issue 50: `PyQuoteGrid` getters clone on every access (LOW)

**Decision:** Do nothing — infrequently accessed.
